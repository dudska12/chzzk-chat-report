# chzzk-chat-report (MVP)

치지직(CHZZK) 라이브 방송의 채팅을 감시하다가, 방송이 종료되면 자동으로
"채팅왕 / 자주 나온 단어 / 방송 분위기" 리포트를 마크다운(+선택적으로 이미지 카드)으로
생성하는 MVP입니다.

여러 BJ가 채널ID만 바꿔서 각자 쓸 수 있도록, 로그인 없이도(공개 채팅 열람) 동작하게 만들었습니다.
지금은 치지직만 지원하고, 숲(SOOP)/유튜브는 이후 어댑터를 추가하는 구조로 확장할 계획입니다.

> **참고**: 방송 화면을 AI(Claude 비전 API)로 직접 분석해서 게임중/대화중/먹방 여부를 더
> 정확히 판단하는 선택 기능이 있습니다(자세한 내용은 아래 "AI 화면 분석" 절 참고). 이 키는
> 배포되는 코드에 내장돼 있지 않습니다 — 각 사용자가 GUI 설정 화면에서 본인 소유의 Anthropic
> API 키를 직접 입력해야만 켜지고, 그 키는 사용자 컴퓨터의 `config.json`(`.gitignore`에 걸려
> 있어 저장소·배포판에 절대 포함되지 않음)에만 저장됩니다. 키를 넣지 않아도 "게임중/대화중"
> 판단은 스트리머가 직접 설정한 카테고리 정보를, "휴식중" 판단은 화면 변화를 감지하는 로컬
> 계산(외부 API 호출 없음, 비용 0원)을 그대로 써서 프로그램 전체가 정상 동작합니다.

## 왜 이렇게 만들었나 (설계 메모)

- **저장소는 순수 fs 기반 (JSON/JSONL)**: 처음엔 `better-sqlite3`(네이티브 모듈, 설치 시
  컴파일 필요)를 썼다가 빌드 문제로 뺐고, 그다음 Node 22.5+ 내장 `node:sqlite`로
  바꿨는데, 이번엔 **Electron이 번들하는 Node 버전이 22.5 미만이면(예: Electron 32는
  Node 20) 이 모듈 자체가 없어서 GUI가 아예 안 켜지는 문제**가 실제로 발생했습니다.
  그래서 지금은 어떤 Node/Electron 버전에서도 무조건 동작하는 순수 `fs` 기반(세션별
  JSON 파일 + 채팅은 JSON Lines로 append)으로 정착했습니다. 채팅 기록은 세션당 많아야
  몇만 줄 수준이라 SQLite 없이도 충분히 빠릅니다.
- **비공식 라이브러리 사용**: 치지직 공식 API는 채팅 "전송"만 지원하고 "읽기(구독)"는
  지원하지 않습니다. 그래서 실시간 채팅 수집에는 비공식 라이브러리(`chzzk` npm 패키지,
  socket.io 기반)를 씁니다. 구조가 바뀌면 깨질 수 있다는 리스크가 있습니다.
- **로그인 불필요**: 공개 채팅 열람은 로그인 쿠키 없이도 가능해서, BJ가 자기 채널ID만
  입력하면 바로 쓸 수 있습니다.
- **플랫폼 어댑터 구조 전제**: `types.ts`의 `ChatMessage`가 공통 포맷이라, 나중에 숲/유튜브용
  collector를 추가해도 `analyzer.ts`/`report.ts`는 그대로 재사용됩니다.

  report.ts           - 분석 결과 -> 마크다운 리포트

  edit-points.ts      - 타임라인에서 휴식/하이라이트만 뽑아 영상 편집용 CSV로 변환 (편집점 내보내기)
  frame-classifier.ts - 방송 화면의 아주 작은 흑백 프레임을 캡처해서 픽셀 변화량만 계산(휴식/

  motion-detector.ts  - 위 픽셀 변화량으로 "화면이 안 바뀌는 상태"가 이어지는지 판정

  vod-playback.ts      - VOD 실제 재생 URL(HLS/DASH) 해석

`collector.ts`의 `ChannelWatcher`가 핵심 엔진이고, CLI(`index.ts`)와 GUI(`gui/main.js`)는
둘 다 이 클래스 하나를 그대로 갖다 쓰는 껍데기입니다. 로직은 한 곳에만 있어서 둘 중 뭘 쓰든
채팅 수집/분석/리포트 결과는 동일합니다.

## 실행 방법 (CLI)

```bash
npm install
npm run build

# 합성 데이터로 리포트 파이프라인 테스트 (네트워크 불필요, 제일 먼저 해볼 것)
npm run demo

# 실제 채널 감시 (채널ID는 치지직 채널 URL 마지막 부분, 예: chzzk.naver.com/live/여기)
node dist/index.js watch <channelId>
```

`watch`를 실행하면:
1. 30초마다 `client.live.status(channelId)`로 라이브 상태를 폴링
2. `OPEN` 감지 시 세션 시작 + 웹소켓 채팅 연결
3. `CLOSE` 감지 시 세션 종료 + `reports/` 폴더에 마크다운 리포트 저장 + 콘솔 출력
4. **Ctrl+C로 직접 종료해도** 그 시점 기준으로 즉시 세션을 마감하고 리포트를 생성합니다.
   (BJ 본인이 아니라 시청자가 프로그램을 켜두고 보다가, 스트리머가 방종하는 걸 보고
   직접 끄는 시나리오를 위한 기능입니다.)

## 클릭 가능한 화면(GUI)으로 실행하기

```bash
# 1. 먼저 루트에서 핵심 로직을 빌드 (한 번만 하면 됨, 코드 수정 시 다시)
npm install
npm run build

# 2. gui 폴더로 이동해서 Electron 앱 실행
cd gui
npm install
npm start
```

창이 뜨면: 왼쪽 사이드바에서 즐겨찾기 채널을 추가하고 토글을 켜서 감시를 시작합니다. 선택한
채널의 실시간 채팅 미리보기(후원은 강조 표시)가 왼쪽에, 오른쪽엔 "동작 로그" / "최종 리포트" /
"타임라인" 탭이 뜹니다. 스트리머가 방종하면 자동으로 리포트 탭으로 전환되고, 그 전에 "종료"
버튼(또는 사이드바 토글 끄기)을 눌러도 즉시 리포트가 생성됩니다. 리포트 탭에는 "내보내기"
(.md 파일 저장)와 "카드 이미지"(PNG 저장) 버튼이 있습니다.

디자인은 사용자가 제공한 목업을 그대로 구현했습니다: 다크 테마, 프레임리스 창(커스텀
타이틀바, 왼쪽 점 3개가 닫기/최소화/최대화), 상태 배지(대기/감시중/완료), 경과시간·메시지수·
후원건수 실시간 카운터, 채팅왕 순위바, 빈도에 비례한 워드클라우드, 긍정/중립/부정 비율 바.

## 여러 채널을 동시에 감시하기 (즐겨찾기, GUI 전용)

시청자/편집자 입장에서 2명 이상의 스트리머를 동시에 관리하는 경우를 위한 기능입니다.

- **즐겨찾기 사이드바**: 왼쪽 사이드바 위쪽 입력창에 채널ID나 방송 URL을 넣고 "+"를 누르면
  즐겨찾기에 추가됩니다. 목록의 각 행은 채널명, 상태 점(회색=대기·초록색=감시중·파란색=완료),
  감시 온/오프 토글, 삭제(×) 버튼으로 구성됩니다. 행을 클릭하면 그 채널의 로그/리포트/타임라인이
  오른쪽 화면에 표시됩니다 — 즉, 여러 채널을 동시에 감시하면서 필요할 때마다 사이드바에서
  클릭해 화면만 전환해 볼 수 있습니다.
- **토글 하나로 시작/종료 + 자동시작 설정을 겸함**: 토글을 켜면 그 즉시 해당 채널 감시가
  시작되고, 동시에 "다음에 앱을 켤 때도 자동으로 이 채널을 감시할지"도 함께 저장됩니다. 토글을
  끄면 지금 감시가 종료되며(진행 중이던 세션이 있었다면 리포트도 생성됩니다) 다음 실행 때도
  자동시작되지 않습니다. 즉 별도의 "자동시작" 설정 화면 없이, 토글 상태 자체가 곧 "지금 켜져
  있는지"와 "앱 재시작 시 자동으로 켜질지"를 동시에 나타냅니다.
- **앱 시작 시 자동 감시**: 토글이 켜진 상태로 앱을 껐다가 다시 켜면, 창이 뜨자마자 그 채널들의
  감시가 자동으로 다시 시작됩니다(수동으로 다시 켤 필요 없음).
- **방송이 끝나도 토글은 계속 켜진 채로, 다음 방송을 자동으로 다시 기다립니다**: 리포트가
  나왔다고 감시가 끝나는 게 아닙니다. 내부적으로 방송 상태를 계속 폴링하고 있어서, 토글을 다시
  켤 필요 없이 다음 방송도 자동으로 잡혀서 또 리포트가 만들어집니다. 사이드바 상태 텍스트가
  "다음 방송 대기 중"으로 바뀌는 게 이 상태입니다.
- **채널마다 완전히 독립적으로 동작**: 채팅 수집·분석·리포트 엔진(`ChannelWatcher`)은 원래부터
  인스턴스마다 독립적으로 설계돼 있어서, 여러 채널을 동시에 띄워도 서로 데이터가 섞이지
  않습니다. 한 채널이 방종해서 리포트가 만들어지는 동안 다른 채널은 계속 채팅을 수집합니다.
- **즐겨찾기는 `config.json`에 `favorites` 배열로 저장**되어, 컴퓨터를 껐다 켜도 목록이
  유지됩니다.

### 백그라운드 상주 (트레이 아이콘 + 컴퓨터 켤 때 자동 실행)

즐겨찾기 자동시작만으로는, 앱을 직접 실행해 켜둔 상태여야만 감시가 이어집니다. 편집자가 매번
직접 앱을 켜지 않아도 되도록, 시스템 트레이에 상주하면서 컴퓨터 부팅 시 자동으로 켜지는
기능을 추가했습니다.

- **닫기(X) = 완전 종료가 아니라 트레이로 숨김**: 창 왼쪽 위 닫기 버튼을 눌러도 프로그램이
  꺼지지 않고 시스템 트레이(작업표시줄 알림 영역)로 숨습니다. 감시는 백그라운드에서 계속
  진행됩니다. 트레이 아이콘을 클릭하면 창이 다시 나타납니다.
- **트레이 메뉴**: 트레이 아이콘을 우클릭(또는 플랫폼에 따라 클릭)하면 "창 열기", 즐겨찾기
  채널별 상태(● 감시 중 / ○ 대기 중 — 클릭하면 그 채널의 감시를 바로 켜고 끌 수 있음), "종료"
  메뉴가 뜹니다. 완전히 프로그램을 끄고 싶을 땐 이 메뉴의 "종료"를 눌러야 합니다.
- **컴퓨터 켤 때 자동 실행**: 설정 화면(톱니바퀴 아이콘)에 새로 생긴 "컴퓨터 켤 때 자동 실행"
  토글을 켜면, OS 로그인 항목에 이 프로그램이 등록되어 컴퓨터를 켤 때마다 자동으로 실행됩니다
  (`app.setLoginItemSettings` 사용, 별도 설치 프로그램 없이 Electron 자체 기능). 즐겨찾기
  자동시작 토글과 같이 켜두면, **컴퓨터만 켜면 즐겨찾기해둔 채널들의 감시가 알아서 다시
  시작되는 구조**가 완성됩니다 — 편집자가 매번 프로그램을 열고 채널을 다시 켤 필요가
  없어집니다.
- **완전 종료 방법**: 트레이 메뉴의 "종료"를 누르면 그때는 실제로 앱이 완전히 꺼지고, 이
  시점에 감시 중이던 모든 채널이 각자 리포트를 만들고 나서 종료됩니다(기존 "Ctrl+C/종료
  버튼으로 즉시 리포트 생성" 로직 그대로 재사용).

### 편의 기능

- **설정 화면**: 타이틀바 오른쪽 톱니바퀴 아이콘을 누르면 chzzk 로그인, 컴퓨터 켤 때 자동
  실행, 고급 설정 열기가 한 화면에 모여 있습니다.
- **방송 URL 붙여넣기 자동 인식**: 채널ID를 따로 찾아 입력하지 않아도, 즐겨찾기 추가 입력창에
  `chzzk.naver.com/live/...` 형태의 방송 URL을 그대로 붙여넣으면 채널ID만 자동으로 뽑아줍니다.

### 라이브 방송 영상 재생 (GUI 전용)

VOD 분석에 실제 다시보기 영상 재생 기능을 붙인 뒤, 라이브 감시 화면에도 같은 걸 붙였습니다.
왼쪽 "실시간 채팅" 패널을 위(영상)/아래(채팅) 반반으로 나눠서, 위에는 지금 감시 중인 채널이
실제로 방송 중이면 그 영상이 뜹니다.

- **VOD보다 오히려 간단합니다.** VOD는 chzzk이 공식 문서로 안 주는 재생 URL 조합 방식을
  오픈소스(yt-dlp) 참고해서 역공학해야 했는데, 라이브는 이미 쓰고 있는 `chzzk` npm 패키지의
  공식 지원 메서드 `client.live.detail(channelId)`가 `livePlayback.media[].path`로 재생
  가능한 HLS(.m3u8) 주소를 바로 내려줍니다. 그래서 `src/live-playback.ts`는 VOD 쪽
  `vod-playback.ts`보다 훨씬 짧습니다.
- **초저지연(LLHLS)보다 일반 HLS를 우선 고릅니다.** `media` 배열에 저지연용(LLHLS)과 일반
  HLS가 같이 올 수 있는데, hls.js 기본 설정으로는 저지연 모드가 최적화돼 있지 않을 수 있어서
  일반 HLS가 있으면 그걸 쓰고, 없으면 LLHLS라도 씁니다(`pickLiveMediaPath()`).
- **채널을 선택했을 때 / 방송이 막 시작됐을 때(`session-start`) / 방송이 끝났을 때
  (`report-ready`)** 각각 영상을 다시 확인합니다 — 방송 중이 아니면 "방송 중이 아니에요"
  안내만 뜨고, 채팅 감시 자체는 영상 재생 성공 여부와 무관하게 그대로 동작합니다.
- **다른 채널/화면으로 전환하면 hls.js 인스턴스를 정리합니다**(`teardownLivePlayer()`) —
  안 하면 화면에 안 보이는데도 스트림을 계속 내려받는 채널이 쌓일 수 있어서, 지금 선택된
  채널 하나만 재생하도록 항상 정리하고 새로 붙입니다.
- **연령 제한 방송**은 VOD와 마찬가지로 로그인 쿠키(`nidAuth`/`nidSession`)를 같이 실어
  보내서 시도합니다.

## 타임라인(방송 히스토리) 탭 (GUI 전용)

리포트 탭 옆에 "타임라인" 탭이 있습니다. 방송을 분당 채팅량 그래프 + 활동 구간(게임중/
대화중/휴식중)으로 한눈에 보여주고, 막대나 구간을 클릭하면 그 시간대 채팅 로그가 아래에
뜹니다. 채팅왕 TOP10 행이나 "유저 지정" 칩을 클릭하면 그 유저가 언제 채팅했는지 세로 눈금으로
표시되고, 총 채팅/첫 채팅/마지막 채팅/후원액/주 활동 구간이 요약됩니다.

**시간 직접 이동 + 확대/축소 (마라톤 방송용)**: 채팅량 차트는 방송이 길어질수록(내부적으로
버킷 개수가 최대 240개 근처로만 유지되도록 버킷 크기를 자동으로 늘림) 막대 하나하나가
얇아져서 클릭하기 어려워지는 문제가 있었습니다. 이를 위해 두 가지를 추가했습니다: (1) 차트
위 입력창에 `1:23:32`나 `1시간23분32초` 같은 형식으로 정확한 시점을 입력하면 그 시간대로
바로 이동하고, (2) `−`/`+` 버튼으로 막대 너비(3px~40px)를 조절할 수 있고 화면보다 넓어지면
가로 스크롤됩니다 — 방송 전체를 훑어보다가 필요한 구간만 확대해서 정밀하게 클릭할 수
있습니다. 확대/축소해도 보던 시간대가 화면 가운데 그대로 유지되도록 스크롤 위치를 비율로
계산해서 복원합니다.

**"게임중/대화중"은 어떻게 판단하나**: 채팅 텍스트만으로는 지금 뭘 하고 있는지 알 방법이
없어서, 화면이나 음성을 분석하는 대신 치지직 API가 스트리머 본인이 직접 설정한 카테고리
정보(게임명, "저스트채팅" 등)를 그대로 씁니다. 30초마다 하던 방송 상태 폴링에서 이 값이
바뀌는 걸 감지해서 구간을 나누기 때문에, 스트리머가 직접 지정한 값 그대로라 정확합니다.

**"휴식중"은 어떻게 판단하나**: 이건 카테고리로 알 수 없는 정보입니다(카테고리를 안 바꾼 채로
자리를 비울 수 있으니까요). 처음엔 "채팅이 오래 잠잠하면 휴식중"으로 판단했는데, 이게 생각보다
신뢰할 수 없는 신호라는 걸 알게 됐습니다 — 스트리머가 자리를 비웠을 때 채팅이 항상 조용해지는
게 아니라, 오히려 "어디감?" 같은 채팅으로 더 늘어날 수도 있기 때문입니다. 그래서 방송 화면에서
아주 작은 흑백 프레임(32×18픽셀)을 짧은 주기(기본 10초)로 계속 뽑아서, 바로 직전 프레임과
픽셀 차이를 계산하는 방식으로 바꿨습니다. **외부 API를 전혀 쓰지 않는 완전 로컬 계산이라
비용이 0원**이고, 방송 감시를 시작하면 항상 자동으로 켜져 있습니다.

- **고정 기준이 아니라 상대 기준**: 게임마다 원래 화면이 얼마나 움직이는지가 완전히 다릅니다
  (액션 게임은 항상 격하게 움직이고, 턴제/비주얼노벨류는 원래 거의 안 움직임). 그래서 고정된
  "이 값 이하면 정적"이 아니라, 그 방송의 최근 변화량 평균 대비 상대적으로 판단합니다.
- **한 번의 판단으로 확정하지 않고, 2단계로 재확인합니다**: 실제 BJ들의 자리비움은 보통
  1분 안팎이라, 확정까지 너무 오래 걸리면 의심이 뜬 시점엔 이미 돌아올 때가 다 됩니다. 그래서
  1단계로 화면 변화가 없는 상태가 연속 2번(약 20초) 이어지면 "휴식 의심"으로 넘어가고, 곧바로
  확정하지 않고 2단계로 약 2초 간격으로 5번 더 몰아서 재확인합니다(같은 HLS 세그먼트를
  중복으로 받아서 "가짜로 변화 없음"이 나오는 걸 피하려고 정확히 1초가 아니라 2초 간격을
  둡니다). 5번 중 4번 이상 정적이어야 통과하는 다수결 방식이라, 20초짜리 판단 하나에 우연히
  낀 잡음(디코딩 노이즈, 순간적인 화면 정지 등) 때문에 잘못 확정되는 걸 줄여줍니다. 화면이
  다시 움직이기 시작하면 복귀로 판단해서 휴식을 종료합니다.
- **한계**: 결국 "화면이 안 바뀐다"는 간접 신호라, 100% 확실하다고 볼 수는 없습니다. 예를
  들어 캠 없이 정지된 화면을 오래 보여주는 콘텐츠(라디오 방송처럼 진행하는 경우 등)는
  실제로 사람이 있어도 휴식으로 오판될 수 있고, 반대로 날씨/파티클 효과처럼 사람이 있든
  없든 화면이 계속 흔들리는 게임에서는 자리비움을 놓칠 수 있습니다.
- **켜는 법**: 별도 설정 없이 방송 감시를 시작하면 자동으로 켜집니다. ffmpeg가 없으면(설치
  실패 등) 이 기능만 조용히 꺼지고 채팅량 기반 추정으로 자동 대체됩니다.

**카테고리 정보가 아예 없는 경우**: 사용 중인 chzzk 라이브러리 버전이나 채널 설정에 따라
카테고리 필드가 안 내려올 수도 있습니다. 이럴 땐 전체를 "대화중"으로 깔아두고 휴식중 추정만
그 위에 얹는 식으로 조용히 대체됩니다 (에러 없이 동작은 계속됨).

**자리비움 판단은 라이브 전용입니다.** 연속된 프레임을 실시간으로 계속 비교해야 하는 방식이라,
VOD의 배치 구조와 근본적으로 안 맞습니다. VOD 분석에서는 채팅량이 잠잠해지는 구간을 휴식으로
추정하는 폴백 로직을 그대로 씁니다.

### 고급 설정 (GUI 전용) — 로컬 분석 로직 세부 조정

설정 화면(⚙️) → "고급 설정 → 열기"에서, 이 문서 위쪽에 나온 휴식 감지/타임라인 판단 로직의
세부 값들을 직접 조절할 수 있습니다. 방송 스타일마다(채팅 속도, 화면이 원래 많이 움직이는
게임인지 등) 기본값이 안 맞을 수 있어서 만든 기능입니다.

- **상태 확인**: 방송 상태 확인 주기.
- **휴식(자리비움) 감지**: 체크 주기, 휴식 의심 전환까지 필요한 연속 정지 횟수, 재확인 샘플
  개수/간격/최소 정지 수, 노이즈 무시 최소 변화량, 정지 판단 민감도, 기준선 계산 샘플 개수.
- **타임라인(채팅 기반) 판단**: 채팅량 집계 기본 단위시간, 최소 구간 길이, 휴식 후보 최소
  연속 잠잠 구간 수.
- **AI 화면 분석**(Claude API 키가 있을 때만 실제로 동작): 화면 분류 기본 간격, 신뢰도
  임계값, 상태 확정까지 필요한 연속 동일 판정 횟수, AI 분위기 요약에 넘길 최대 채팅 샘플 수.

민감도 계열 값은 로우레벨 계수라 잘못 만지면 오탐이 늘거나 정상 상황을 놓칠 수 있다는 경고
문구를 모달 상단에 같이 둡니다. "초기값으로 되돌리기" 버튼으로 언제든
`DEFAULT_ANALYSIS_SETTINGS`(예전 하드코딩 값과 동일) 값으로 되돌릴 수 있습니다. 저장한 값은
그 다음 새로 시작하는 감시/VOD 분석부터 적용되고, 이미 진행 중인 감시는 새로 적용하려면
다시 시작해야 합니다.

## 편집점 내보내기 (이 프로그램의 원래 목적)

방송 중 스트리머가 자리를 비운 구간, 채팅이 몰린 구간, 후원이 몰린 구간을 "영상 편집할 때
바로 써먹을 수 있는 시각 목록"으로 정리해서 내보내는 기능입니다. 실시간으로 자리비움을 감지해
편집 참고 자료로 쓰고 싶다는 게 이 프로그램을 만든 원래 목적이었는데, 그 목적에 가장 직접
맞닿아 있는 기능입니다.

- **시각 기준은 항상 "방송 시작 후 경과 시간"**: 예를 들어 `00:32:10`이면 "방송 시작하고
  32분 10초 지난 시점"이라는 뜻입니다. 다운로드한 VOD(다시보기) 영상의 재생 위치와 그대로
  맞아떨어지도록 일부러 시계 시각이 아니라 이 상대 시간으로 씁니다.
- **자동 저장**: 방송이 끝날 때마다(자동 감지든 수동 종료든) `reports/` 폴더에 리포트(.md)와
  나란히 `채널명_날짜시간_editpoints.csv` 파일이 자동으로 남습니다. 버튼을 따로 안 눌러도
  항상 만들어집니다(단, 편집점으로 잡힌 구간이 하나도 없으면 생략됩니다).
- **GUI에서 수동 내보내기**: 타임라인 탭 상단의 "편집점 내보내기" 버튼으로 원하는 위치에
  CSV로 저장할 수 있습니다. 자동 저장분과 내용은 같고, 저장 위치만 직접 고를 수 있는
  버전입니다.
- **CSV에 들어가는 내용**: 구분(휴식/채팅 폭발/후원 몰림/채팅 잠잠), 시작, 종료(구간이 있는
  휴식만), 길이(초), 설명 — 5개 열입니다. 엑셀에서 열어도 한글이 안 깨지도록 UTF-8 BOM을
  붙여서 저장합니다.
- **휴식(자리비움) 구간이 핵심**: 화면 변화 감지(또는 채팅량 추정)로 확정된 "휴식중" 구간이
  시작~종료 범위로 들어갑니다. 채팅 폭발/후원 몰림/채팅 잠잠 하이라이트는 단일 시점으로
  들어갑니다(범위가 아니라 그 순간을 전후로 살펴보라는 의미).

## 다시보기(VOD) 채팅으로 분석하기 (GUI 전용)

라이브를 실시간으로 지켜보지 못했거나, 이미 끝난 방송을 나중에 편집 참고용으로 분석하고
싶을 때를 위한 기능입니다. 다시보기 영상 URL 하나만 넣으면, 그 영상의 채팅을 처음부터 끝까지
전부 모아서 라이브 감시와 똑같은 리포트/타임라인/편집점 CSV를 만들어줍니다.

- **사용법**: 왼쪽 사이드바 위쪽 "즐겨찾기 / VOD 분석" 세그먼트에서 "VOD 분석"을 선택하고,
  다시보기 영상 URL(`chzzk.naver.com/video/12345678` 형태) 또는 영상 번호만 입력한 뒤 "+"를
  누르면 바로 분석이 시작됩니다. 목록에 작업이 추가되고, 채팅을 얼마나 모았는지 진행률이
  실시간으로 표시됩니다.
- **즐겨찾기와 다른 점 — "감시"가 아니라 "한 번 실행하는 작업"**: 즐겨찾기는 토글을 켜두면
  계속 방송을 기다리는 상주형이지만, VOD 분석은 시작하면 끝까지 실행되고 끝나는 일회성
  배치 작업입니다. 그래서 토글이 아니라 목록(카드) 형태로 보여주고, 상태도 "채팅 수집 중 →
  분석 완료" 또는 "분석 실패"로만 갈립니다.
- **완료되면 화면이 100% 동일**: 목록에서 완료된 작업을 클릭하면 라이브 감시와 완전히 같은
  "동작 로그 / 최종 리포트 / 타임라인" 탭이 뜹니다. 채팅왕/단어 빈도/분위기/후원 집계는 물론,
  타임라인 탭의 유저 지정·구간 클릭·"편집점 내보내기" 버튼까지 전부 그대로 씁니다 — 화면
  코드를 라이브용과 VOD용으로 따로 만들지 않고 100% 재사용했습니다.
- **"정밀분석"(선택, Claude API 키 필요)**: 기본 분석(채팅+카테고리)이 끝난 카드에 "정밀분석"
  버튼이 나타납니다. 눌러야만 시작되는 옵트인 작업이고, 실제 화면을 캡처해서 AI 분류로
  게임중/대화중/휴식중(먹방 포함)을 다시 판단한 뒤 같은 리포트/타임라인/편집점 CSV를
  덮어씁니다. 자세한 동작 방식은 위 "AI 화면 분석" 절 참고.
- **채팅 수집 원리**: 치지직 웹 플레이어가 다시보기 재생 중 채팅을 동기화해서 보여줄 때
  내부적으로 호출하는 REST API(`/service/v1/videos/{videoNo}/chats`)를 그대로 씁니다. 이
  요청 하나에 최대 50개 채팅이 오고, 응답에 담긴 다음 커서 값으로 반복 호출해서 영상 처음부터
  끝까지 순회합니다. 이 엔드포인트는 치지직이 공식 문서로 공개한 API가 아니라서, 페이지네이션이
  정확히 어떤 규칙으로 끝까지 중복·누락 없이 도는지는 실제 영상으로 끝까지 검증하지
  못했습니다 — 그래서 종료 조건을 여러 겹(다음 커서가 더는 진행하지 않을 때 / 영상 길이를
  넘어설 때 / 빈 페이지가 오면서 이번 페이지에 새로 추가된 게 없을 때)으로 방어적으로
  짜뒀습니다.
- **시간 기준**: 채팅마다 같이 오는 "영상 재생 위치 기준 경과 시간"을 방송 시작 시각에 더해서
  절대 시각으로 맞춥니다. 다시보기 영상은 예고편이 잘리는 등 실제 방송과 길이가 어긋날 수
  있어서, 방송 당시 실제 시각보다 이 재생 위치 기준이 편집점(항상 "방송 시작 후 경과 시간"
  기준)과 더 정확히 맞아떨어집니다.
- **방송 시작 시각은 `liveOpenDate`(실제 방송 시작 시각) 기준입니다.** chzzk API에는 이것
  말고도 `publishDate`/`publishDateAt`(다시보기 영상이 "게시"된 시각)이 따로 있는데, 이건
  방송이 끝나고 처리가 완료된 뒤에 찍히는 값이라 시작 시각으로 쓰면 방송 전체가 실제보다
  길이만큼 뒤로 밀려 보입니다.

**로그인이 필요할 수 있습니다.** 다시보기 영상 정보 조회(`/service/v1/videos/{videoNo}`)는
`exposure: true`인 완전히 공개된 영상이어도 로그인 없이는 빈 응답이 오는 경우가 있습니다.
"영상 정보를 찾을 수 없습니다" 에러가 나면 십중팔구 이 경우입니다. 설정 화면(톱니바퀴 아이콘)의
"chzzk 로그인" 버튼을 누르면 실제 치지직/네이버 로그인 페이지가 새 창으로 뜹니다 — 비밀번호는
이 프로그램이 아니라 그 페이지에 직접 입력되고, 로그인이 완료되면 필요한 쿠키(`NID_AUT`,
`NID_SES`)를 자동으로 감지해서 저장한 뒤 창이 닫힙니다. 이 로그인은 즐겨찾기(라이브 감시)와
채널 조회에도 함께 적용되고, 연령 제한 방송의 채팅 열람도 이걸로 가능해집니다. 로그인 세션이
만료되면 같은 버튼으로 다시 로그인하면 됩니다.

**한계와 알아둘 점**:
- **카테고리(게임명)는 영상 전체에 하나만 적용됩니다.** 라이브 감시는 30초마다 폴링해서
  방송 중 카테고리가 바뀌는 걸 시간대별로 잡아내지만, 다시보기 영상 메타데이터엔 그런
  시점별 이력이 없이 대표 카테고리 하나만 내려옵니다. 여러 게임을 넘나든 방송이면 방송
  흐름 요약의 정확도가 떨어질 수 있습니다(채팅량 기반 활동 구간 추정은 별개로 계속 동작하니
  완전히 어긋나지는 않습니다).
- **앱을 재시작하면 VOD 작업 목록 자체는 사라집니다.** 즐겨찾기와 달리 파일에 저장해두지
  않는 임시 목록입니다(재실행해도 카드가 다시 안 뜸). 다만 그동안 만들어진 리포트/편집점
  CSV 파일은 `reports/` 폴더에 이미 저장돼 있으니 데이터 자체가 사라지는 건 아닙니다.
- **아직 채팅을 수집하는 중인 작업을 목록에서 지워도, 진행 중이던 수집 자체는 백그라운드에서
  계속됩니다**(취소 기능은 아직 없습니다). 다 끝나면 다시 목록에 나타납니다.

### VOD 영상 재생 + 채팅 검색 (GUI 전용)

VOD 분석 화면은 라이브 감시 화면의 "실시간 채팅" 패널을 그대로 재사용했었는데, VOD 작업은
채팅이 실시간으로 오지 않고(처음에 한 번에 다 모아옴) 이벤트 자체가 안 와서 그 패널이 항상
빈 채로 떠 있었습니다. 그 자리를 위(다시보기 영상) / 아래(채팅 검색) 반반 레이아웃으로
바꿨습니다.

- **재생 URL 해석 (`src/vod-playback.ts`)**: chzzk은 이 과정을 공식 문서로 공개하지 않아서,
  활발히 유지되는 오픈소스 프로젝트 [yt-dlp의 CHZZKVideoIE
  구현](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/chzzk.py)을 참고해서
  맞췄습니다. `/service/v3/videos/{videoNo}`로 `videoId`/`inKey`/`vodStatus`/
  `liveRewindPlaybackJson`을 받아온 뒤, `vodStatus === "ABR_HLS"`이면 DASH(.mpd) 매니페스트
  (`https://apis.naver.com/neonplayer/vodplay/v1/playback/{videoId}?key={inKey}&...`)를,
  그 외(일반/구버전/수동 업로드 영상)엔 `liveRewindPlaybackJson` 안의 `media[0].path`(HLS
  .m3u8)를 씁니다. 로그인 쿠키(`nidAuth`/`nidSession`)가 있으면 같이 실어 보내서 연령 제한
  영상도 시도합니다.
- **재생은 hls.js(HLS)/dash.js(DASH)로** — 둘 다 npm 의존성으로 등록해두고 빌드된 파일을
  `gui/renderer/vendor/`에 복사해서 오프라인에서도 동작하게 했습니다(CDN 의존 없음).
- **타임라인 막대/구간을 클릭하거나 채팅 검색 결과를 클릭하면 영상도 그 지점으로 이동합니다.**
  표준 `HTMLMediaElement` API의 `currentTime`을 그대로 설정합니다.
- **채팅 검색은 닉네임/본문 부분일치**로 이미 수집된 채팅 전체(`getMessagesInRange(0, ∞)`)를
  훑어 최대 200개까지 보여줍니다. 아직 채팅 수집이 안 끝난 작업(진행 중)은 검색 결과가
  비어있을 수 있습니다 — 수집이 끝나야 검색 대상 메시지가 채워집니다.
- **검색창을 비워두면 영상 재생 위치와 동기화된 채팅이 뜹니다.** 채팅 수집이 끝나면
  (`phase === "done"`) 전체 메시지를 한 번만 통째로 받아와 시간순으로 캐시해두고, 영상이
  재생되는 동안(`timeupdate`, 400ms 간격으로 스로틀) 이진 탐색으로 "지금까지 나온 채팅"
  구간만 다시 그립니다.
- **자동 재생이 안 되는 경우를 위한 대비책**: 재생 URL 해석에 실패하거나(비공식 API라 응답
  구조가 바뀌면 실패할 수 있음), DRM이 걸린 유료/멤버십 전용 다시보기처럼 hls.js/dash.js만으로
  재생이 안 되는 경우, "브라우저에서 열기" 버튼으로 실제 chzzk 페이지를 열어서 볼 수 있습니다.

## 지금 리포트에 들어가는 내용

기본 집계뿐 아니라 이미 수집된 데이터(타임라인 구간, 채팅 로그)를 다시 엮어서 "숫자 나열"이
아니라 조금 더 해석에 가까운 내용도 넣습니다.

  (타임라인 탭과 같은 데이터를 재사용 — 카테고리 정보가 하나도 없으면 이 섹션 자체가 생략됩니다)
- 채팅왕 TOP 10, 후원 TOP 5 (금액 기준)
- **시청자 참여 구조**: 채팅왕 TOP 10이 전체 채팅에서 차지하는 비중, 방송 중 딱 한 번만
  채팅한 "눈팅형" 시청자 비율
- **후원과 방송 흐름 교차**: 후원이 게임중/대화중/휴식중 중 어디에 몰렸는지, 후원 TOP 5와
  채팅왕 TOP 10이 얼마나 겹치는지
- **그 순간 채팅**: 채팅이 몰린 구간·최다 후원 구간에서 실제로 오간 채팅 몇 줄을 발췌
  (근사치 추출이라 정말 대표성 있는 발췌인지는 사람이 리포트를 보고 판단하는 게 좋습니다)
- 자주 나온 단어 TOP 20 (기본은 정규식 토큰화, Kiwi 모델 설치 시 형태소 분석 기반으로 자동 전환)
- 방송 분위기 라벨/이모지 + 긍정·중립·부정 비율 + 채팅이 몰린 하이라이트 구간

## 선택 기능 (기본은 꺼져 있고, 설정하면 자동으로 켜짐)

### AI 화면 분석 (Claude 비전 API, 선택)

게임중/대화중/휴식중(먹방 포함) 판단을 카테고리·채팅량 추정보다 더 정확하게 하고 싶으면,
실제 방송 화면을 캡처해서 Claude 비전 API로 직접 분류하는 기능을 켤 수 있습니다. 기본값은
꺼짐이고, GUI 설정 화면(⚙ → "Claude API 키")에 본인의 Anthropic API 키를 입력하면 그 순간부터
켜집니다 — 키는 이 컴퓨터의 `config.json`에만 저장되고(`.gitignore`에 걸려 있어 저장소에는
절대 올라가지 않습니다) Anthropic API 호출 외에는 어디로도 전송되지 않습니다. 키가 없으면
이 기능만 조용히 꺼진 채로, 카테고리 기반 게임중/대화중 판단과 화면 변화 감지 기반 휴식중
판단(둘 다 완전 로컬·무료)은 그대로 정상 동작합니다.

- **라이브 감시**: 방송 중 `frameIntervalMs`(기본 90초)마다 화면을 캡처해 분류합니다. 같은
  판정이 `visionConfirmCount`(기본 2)번 연속으로 나와야 확정해서, 프레임 한 장의 오분류로
  타임라인이 튀지 않게 합니다. 신뢰도가 `visionConfidenceThreshold`(기본 0.75) 미만인 응답은
  버립니다. 휴식 의심(화면 변화 없음)이 감지되면, 확정 전에 AI에게 한 번 더 물어봐서 정말
  자리비움인지(로딩·메뉴 화면처럼 정적이지만 자리비움은 아닌 경우와) 구분합니다.
- **VOD "정밀분석"**: 다시보기는 채팅+카테고리 기반 기본 분석이 먼저 끝난 뒤, 사이드바 카드의
  "정밀분석" 버튼을 눌러야 시작되는 별도 옵트인 작업입니다. 영상 전체를 촘촘한 간격으로 한 번만
  순차 캡처해두고, 성긴 간격으로 먼저 분류한 다음 인접 구간의 판정이 달라지는 지점만 촘촘한
  프레임으로 다시 물어봐서 API 호출 수를 크게 줄입니다. 끝나면 같은 리포트/타임라인/편집점
  CSV가 화면 분석 결과로 자동으로 덮어써집니다. 진행 중엔 "정밀분석 취소" 버튼으로 언제든
  멈출 수 있고, 앱을 끄면 자동으로 취소됩니다.
- **먹방(EATING) 감지**: 게임 카테고리를 그대로 켜둔 채 식사 방송을 해도, 화면 분석이 이를
  감지하면 "휴식중(먹방)"으로 타임라인·편집점에 따로 표시됩니다.
- **비용**: 호출 1회당 약 $0.002(Haiku 기준 추정치)입니다. GUI 상단 배지("AI 분석: N회 호출 ·
  약 $x.xxx")에서 지금까지 호출 횟수/추정 비용을 실시간으로 볼 수 있습니다.
- **필요 조건**: `ffmpeg`(캡처용, `ffmpeg-static`으로 함께 설치됨)과 Anthropic API 키. 세부
  간격/임계값/확정 횟수는 고급 설정에서 조절할 수 있습니다.

### 형태소 분석 기반 단어 추출 (Kiwi)

기본은 정규식으로 대충 자르는 수준입니다. 다음 명령으로 Kiwi 모델(약 90MB)을 받으면
`wordFrequency()`가 자동으로 명사(NNG/NNP)만 뽑아내는 방식으로 전환됩니다.

```bash
npm run setup:kiwi
```

설치된 `kiwi-nlp` 패키지 버전에 맞는 모델을 GitHub 릴리즈에서 받아 `models/kiwi/`에
풀어놓습니다. `tar` 명령이 필요합니다(Windows는 10 1803 이상이면 내장). 안 받아도 프로그램은
정상 동작하며, 기존 정규식 방식으로 계속 돌아갑니다.

## 설치 파일로 패키징하기 (배포용)

`electron-builder`로 실제 설치 파일(Windows는 NSIS `.exe`, macOS는 `.dmg`, Linux는
`.AppImage`)을 만들 수 있게 루트 `package.json`에 설정해뒀습니다.

```bash
npm install       # electron/electron-builder 포함해서 설치
npm run dist       # 빌드(tsc) + 현재 OS용 설치 파일 생성 (release/ 폴더에 결과물)

# 특정 플랫폼만 지정하려면
npm run dist:win
npm run dist:mac
npm run dist:linux

# 설치 파일 없이 압축 풀린 상태로만 빠르게 확인하고 싶으면
npm run dist:dir
```

- **Electron 실행 파일을 실제로 내려받는 단계라 인터넷 연결이 필요합니다** — GitHub 릴리즈
  자산에서 내려받는데, 사내망/방화벽에서 막혀 있으면 실패할 수 있습니다(이 저장소를 만든
  샌드박스 환경 자체가 이 다운로드가 막혀 있어서, 여기서는 설정값 검증까지만 하고 실제
  설치 파일 생성은 사용자 컴퓨터에서 해봐야 합니다).
- **`../dist`(빌드된 핵심 로직) + `gui/`(Electron 앱) + 운영 의존성만** 패키지에 포함되도록
  `build.files`에 지정해뒀습니다. `src/`, `scripts/`, 개발용 의존성(`typescript`,
  `electron` 자체 등)은 제외됩니다. `ffmpeg-static`의 실행 파일은 asar 안에서 직접 실행이
  안 되므로 `asarUnpack`으로 압축을 풀어둡니다.
- **Windows는 기본적으로 "관리자 권한 없이, 사용자 계정 폴더에 설치"** 되도록
  (`perMachine: false`) 설정해뒀습니다 — `config.json`/`data/`/`reports/`가 전부 설치
  폴더 기준 상대 경로에 저장되는 구조라, 만약 나중에 "관리자 권한 설치(Program Files)"로
  바꾸면 일반 사용자 권한으로는 이 파일들에 못 쓸 수 있습니다. 실제 설치 후 꼭 로그인/
  즐겨찾기 저장이 되는지 확인해보세요.
- **아이콘**: `gui/assets/app-icon.png`(256×256)를 그대로 씁니다. electron-builder가 여기서
  자동으로 `.ico`/`.icns`를 만들어주지만, 화질을 더 신경쓰고 싶으면 1024×1024 원본으로
  바꿔주는 게 좋습니다.
- **코드 서명은 설정하지 않았습니다** — 서명 안 된 설치 파일은 Windows SmartScreen이나
  macOS Gatekeeper가 "알 수 없는 게시자" 경고를 띄울 수 있습니다(악성코드는 아니고, 서명
  인증서가 없다는 뜻입니다). 배포 규모가 커지면 코드 서명 인증서 구매를 고려해보세요.

## 다음 단계로 고려할 것들

1. **숲(SOOP) 어댑터 추가**: `collector.ts`와 동일한 인터페이스로 `SoopWatcher`를 만들어서
   `ChatMessage`만 맞춰 넣으면 나머지 파이프라인은 그대로 재사용됩니다.
2. **비공식 API 리스크 관리**: 치지직/숲 쪽 웹소켓 구조가 바뀌면 collector가 깨질 수 있으니,
   연결 실패 시 사용자에게 알림을 주는 에러 핸들링이 필요합니다.
3. **코드 서명**: 배포 규모가 커지면 Windows/macOS 코드 서명 인증서를 적용해 보안 경고를
   없애는 단계.

## 검증

핵심 파이프라인은 `npm run demo`(합성 데이터로 채팅왕/단어빈도/후원 집계/타임라인/휴식 감지/
AI 화면 분석 우선순위/먹방 매핑/편집점 CSV까지 전부 검증, 회귀 15개 항목 전부 OK) + 루트
컴파일(`npx tsc -p .`)로 항상 재검증합니다. GUI 쪽은 `main.js`/`preload.js`/`renderer.js`
문법 검사(`node --check`), `window.api.*`(렌더러) ↔ `preload.js` 노출 이름, `ipcRenderer.invoke`
↔ `ipcMain.handle` 채널, `el("...")`(렌더러) ↔ `index.html` DOM id, 중복 DOM id 여부를
스크립트로 교차 검증합니다. 이 환경엔 화면이 없어서 GUI 창을 실제로 띄워보거나 실제 chzzk
네트워크로, 또는 실제 Claude API 키로 화면 분석을 끝까지 돌려보는 것은 사용자 컴퓨터에서
확인이 필요합니다.

**API 키 취급 방침**: Claude API 키는 코드 어디에도 내장돼 있지 않습니다. 각 사용자가 GUI
설정 화면에서 본인 소유의 키를 직접 입력해야만 AI 화면 분석 기능이 켜지고, 그 값은
`.gitignore`에 걸려 있는 `config.json`에만 로컬로 저장됩니다 — 이 파일은 저장소에도, 빌드된
배포판에도 포함되지 않습니다(`electron-builder`의 `files` 목록에서 명시적으로 제외).
키를 입력하지 않은 사용자도 카테고리 기반 게임중/대화중 판단과 화면 변화 감지 기반 휴식중
판단(둘 다 완전 로컬/무료)은 그대로 정상 동작합니다.
